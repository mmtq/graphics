Step 1

Animate a Single Box

gsap.to()

Interpolates target element properties from their current state to new values using GPU-accelerated transforms.

Box 1

Key Concepts

  • What is a "Tween"? Short for in-between. A tween smoothly interpolates properties of a target object between a start and end state over a specified duration.
  • gsap.to(target, vars) syntax:
    • target: CSS selector string (e.g. "#box-1"), DOM element, or array of elements.
    • vars: Object containing CSS properties to animate (x, y, rotation, scale, backgroundColor) plus timing options (duration, ease).
  • Transforms over layout: Under the hood, GSAP's x and y translate elements via CSS transform: translate(...), which runs on the GPU and avoids costly browser layout thrashing (unlike top and left).
Code Reference src/step1.ts 
import gsap from 'gsap';

// Animate from current state to new values
gsap.to('#box-1', {
  x: 220,
  rotation: 360,
  scale: 1.2,
  backgroundColor: '#f59e0b',
  duration: 1.2,
  ease: 'power2.out'
});

Experiments & Modifications to Try:

  1. Add infinite oscillation: Add repeat: -1 and yoyo: true into the vars object in src/step1.ts.
  2. Morph shape: Add borderRadius: "50%" to transform the square into a circle during motion.
  3. Arc trajectory: Add y: -60 alongside x: 220 to make the box jump upward in an arc.

Compare to(), from(), and fromTo()

Core Methods

Method Breakdown & Comparison

gsap.to(target, toVars)

Animates from the element's current computed state to the values defined in toVars.

Best for: User interactions, button hover/clicks, responsive state shifts.

gsap.from(target, fromVars)

Animates from specified values to the element's natural CSS layout position.

Best for: Entrance reveals (start invisible/shifted and land in regular layout).

gsap.fromTo(target, fromVars, toVars)

Explicitly defines both starting and destination states. Overrides any prior inline styles.

Best for: Deterministic loops, complex component re-mounts.
⚠️
The Classic gsap.from() Gotcha: If a user triggers gsap.from() again while the first animation is halfway through, GSAP reads the intermediate position as the new destination! Use gsap.fromTo() or kill prior tweens when re-triggering entrance animations.
Code Reference src/step2.ts 
// 1. to: moves forward from wherever it is
gsap.to('#box-to', { x: 180, rotation: 180, duration: 1 });

// 2. from: starts at x:180 and returns to natural CSS state
gsap.from('#box-from', { x: 180, opacity: 0.1, duration: 1 });

// 3. fromTo: forces both boundaries explicitly
gsap.fromTo(
  '#box-fromto',
  { x: -30, opacity: 0.2, scale: 0.6 },
  { x: 180, opacity: 1, scale: 1, duration: 1 }
);

Experiments & Modifications to Try:

  1. Observe the "stuck" bug: Click the "Run from()" button 4 times rapidly while the box is moving. Notice how it gets stuck halfway. Then try doing the same to "Run fromTo()".
  2. Modal pop entrance: In src/step2.ts, modify runFrom to use { y: -80, scale: 0.5, opacity: 0, ease: 'back.out(2)' }.

Experiment with Easing Functions

Acceleration Curves

Eases define the rate of change over time. Test how different curves (physics bounce, spring elasticity, power deceleration) change the mood of the animation.

Ease
gsap.to("#box-easing", { x: 240, duration: 1.4, ease: "power2.out" });

Understanding Easing Curves

An ease dictates how an animation accelerates and decelerates across its duration. GSAP's naming convention follows: <type>.<direction>.

Direction Behavior Primary UI Use Case
.out Starts fast, slows down at the end UI Standard: elements entering, expanding, or responding to clicks.
.in Starts slow, accelerates into destination Elements exiting the screen or falling due to gravity.
.inOut Slow start, fast middle, slow finish Seamless loops, camera pans, loading bars.

Configurable Curves

  • back.out(overshoot): Travels past destination before snapping back. Default overshoot is 1.7. Passing 3 produces a much more exaggerated snap.
  • elastic.out(amplitude, period): Simulates a guitar string or rubber band. Smaller period values yield rapid, tight vibrations.
  • steps(n): Discretizes time into n steps, ideal for retro arcade graphics or sprite-sheet animations.

Experiments & Modifications to Try:

  1. Compare power curves: Switch between power1.out (gentle) and power4.out (aggressive brake) to feel deceleration dynamics.
  2. Exaggerate bounce: Test back.out(4) in src/step3.ts to see the dramatic rubber-band recovery.
  3. 8-bit walk cycle: Set ease to steps(4) with duration: 0.8 to create a classic pixelated step motion.
Step 4

Timeline: Overlaps & Stagger

gsap.timeline()

Sequences animations seamlessly. Uses the position parameter ("<0.2", "-=0.15") to overlap steps, and stagger to delay sequential elements.

Featured

Mastering GSAP Timelines

Position Parameter Stagger Chaining Defaults

Why Use Timelines?

Managing sequential animations with manual delay properties is brittle: changing the duration of step 1 requires manually recalculating all subsequent delays. A gsap.timeline() orchestrates choreographies automatically.

The Position Parameter (Timeline Superpower)

Value Meaning Effect
(omitted) End of previous tween Standard sequence (one after another)
"<" Start of previous tween Plays completely synchronized in parallel
"<0.2" 0.2s after previous starts Overlapping cascade (fluid motion)
"-=0.3" 0.3s before previous finishes Smooth lead-in overlap
"+=0.5" 0.5s after previous finishes Introduces a deliberate pause / gap
Code Reference src/step4.ts 
const tl = gsap.timeline({
  defaults: { duration: 0.5, ease: 'power2.out' }
});

tl.from('#tl-badge', { x: -40, opacity: 0 })
  // Starts 0.2s into the badge animation (overlap)
  .from('#tl-title', { y: 20, opacity: 0 }, '<0.2')
  // Staggers tags by 100ms each, starting before title finishes
  .from('.tl-item', {
    scale: 0,
    opacity: 0,
    stagger: 0.1,
    ease: 'back.out(1.8)'
  }, '-=0.15')
  .from('#tl-btn', { y: 15, opacity: 0 }, '<0.2');

Experiments & Modifications to Try:

  1. Change stagger origin: In src/step4.ts, replace stagger: 0.1 with stagger: { each: 0.1, from: 'center' } or from: 'end'.
  2. Total synchronization: Change "<0.2" on the title to "<" to see badge and title pop in together.

Playback Control API

Every Timeline or Tween instance is a stateful controller object providing complete programmatic control:

Method Description
tl.play() Plays forward from the current playhead position.
tl.pause() Freezes the playhead at the current exact millisecond.
tl.reverse() Plays in reverse back toward time 0.
tl.restart() Rewinds the playhead to 0 and begins playing forward.
tl.timeScale(speed) Sets playback speed multiplier (0.5 = slow motion, 2.0 = double speed).
tl.progress(0-1) Getter & setter for progress from 0.0 (start) to 1.0 (complete).

Two-Way Scrubbing with onUpdate

By passing { paused: true } and an onUpdate callback, we keep an HTML range slider synchronized with GSAP's internal playhead, while also letting user slider inputs scrub the animation directly.

Code Reference src/step5.ts 
const tl = gsap.timeline({
  paused: true,
  onUpdate: () => {
    const prog = tl.progress();
    slider.value = (prog * 100).toFixed(1);
  }
});

// Dragging the slider scrubs the animation
slider.addEventListener('input', () => {
  tl.pause();
  tl.progress(parseFloat(slider.value) / 100);
});

Experiments & Modifications to Try:

  1. Frame-by-frame scrub: Pause the animation and drag the scrubber slowly across the bar. Notice how transforms, rotation, scale, and color blend smoothly at any sub-pixel point.
  2. Infinite breathing timeline: Pass { repeat: -1, yoyo: true } into gsap.timeline(...) in src/step5.ts. You can still pause and scrub it while it loops!
